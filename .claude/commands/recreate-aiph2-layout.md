# Purpose

Build a self-contained course-mirror folder at `DEST_DIR` for an AIPH2-style Circle course, populated by driving the `using-circle-courses` skill against `COURSE_NAMESPACE`. The target shape and the source-of-content mapping are described in full inside this prompt — no external reference directory is read. Follow the `Workflow`; the layout spec, naming rules, and per-folder file inventory are encoded in the `Instructions` section.

## Variables

DEST_DIR: `~/aiph2-mirror` (absolute or `~`-prefixed path; created if missing; if non-empty the workflow stops and asks before writing)
COURSE_NAMESPACE: `aiph2` (key from `~/.claude/skills/using-circle-courses/courses.json`; defaults to `aiph2` when omitted)
CIRCLE_SKILL: `using-circle-courses`

## Instructions

- This prompt is a **layout-bootstrapper**, not a learning agent. It creates a known directory shape and fills it with Circle-fetched artifacts. It does **not** clean transcripts, build flashcards, or run quests.
- The full target layout (everything below is the contract — do not invent extra folders, do not omit any of these):

  ```
  DEST_DIR/
    LAYOUT.md                                  # generated by this prompt
    weeks/                                     # one folder per lesson day, Circle-sourced
      <wXdY-YYYY-MM-DD-slug>/                  # e.g. w1d1-2026-04-20-kick-off
        slides/                                # PDF slide decks attached on the lesson page
          *.pdf
        transcripts/
          transcript-raw.md                    # transcript export from Circle (markdown, raw)
          transcript-raw.txt                   # transcript export from Circle (plain text, raw)
          transcript.md                        # placeholder — user-cleaned later, NOT fetched
        materials/                             # lesson attachments
          *.docx                               # quest briefs and other handouts
          quest-<n.m>-<slug>/                  # per-quest sub-folder for multi-file quests
            *
    extras/                                    # off-curriculum live sessions, Circle-sourced
      <YYYY-MM-DD-slug>/                       # e.g. 2026-04-23-pucek-angel-investor
        transcript.md                          # cleaned transcript from the recording post
        transcript.txt                         # plain-text transcript export
        chat.txt                               # Zoom-style chat log attached to the same post
    setup/                                     # onboarding/orientation, Circle-sourced
      <slug>/                                  # e.g. circle-tour, case-przestrzen
        transcript-raw.txt                     # raw transcript export
        transcript.md                          # placeholder — user-cleaned later, NOT fetched
    references/                                # top-level pinned reference attachments
      *.docx                                   # e.g. tooling list, glossary
    notes/                                     # user-generated; created empty
  ```

- Top-level subtrees and how each is handled:
  - `weeks/` — **Circle-sourced**. Discover lesson set from Circle's lessons space (`lessons_path` in the namespace config). For each lesson, derive the folder slug as `wXdY-YYYY-MM-DD-<kebab-slug>` where `wX` = week index, `dY` = day index inside that week (1 or 2 typically), `YYYY-MM-DD` = lesson date, `<kebab-slug>` = lowercase hyphenated form of the lesson title. Download slides, materials, and transcript exports.
  - `extras/` — **Circle-sourced**. Discover from the live-session-recordings space. For each recording post, derive `<YYYY-MM-DD-kebab-slug>` from post date + title. Download transcript (both .md and .txt) and the Zoom chat log.
  - `setup/` — **Circle-sourced**. Onboarding/orientation transcripts (typically found in `prework`, `webinars_kb`, or `live_session_recordings` — discover where they actually live). Slug is a short kebab-case label (e.g. `circle-tour`, `case-przestrzen`). Download `transcript-raw.txt`; create empty `transcript.md` placeholder.
  - `references/` — **Circle-sourced**. Top-level pinned attachments on `program_artifacts` (or wherever the course pins reference docs — discover if needed). Preserve original filenames.
  - `notes/` — **user-generated**. Create the empty directory only.
  - `digital-twin/` — **excluded by design** (NOT created). It is the user's own Quest 1.1 work for **their own product** — not on Circle and not transferable. In `LAYOUT.md`, just point at the quest brief that lands inside `weeks/<first-day kick-off lesson>/materials/quest-1.1-digital-twin/` and explain that the user authors `instructions.md` (system prompt for their own AI assistant about their own product), an optional `README.md`, and `data/*.md` knowledge-base files. Do **not** describe a fixed file count, fixed dimensions, or any product-specific shape — those belong to whoever runs Quest 1.1.
  - `learning/` and `learn-agent/` — **excluded by design** (NOT created). Downstream tooling (incremental-learning store and active-learning agent), not course material. Mention them in `LAYOUT.md` so the omission is explicit.

- Source-of-content mapping (write this verbatim into `LAYOUT.md` — it is the contract this prompt fulfills):
  - `weeks/<key>/slides/*.pdf` ← Circle lesson page attachment download
  - `weeks/<key>/transcripts/transcript-raw.md` ← Circle lesson page transcript export (markdown variant)
  - `weeks/<key>/transcripts/transcript-raw.txt` ← Circle lesson page transcript export (plain-text variant)
  - `weeks/<key>/transcripts/transcript.md` ← **user-cleaned** (placeholder only — empty file)
  - `weeks/<key>/materials/*.docx` ← Circle lesson page attachment download
  - `weeks/<key>/materials/quest-<n.m>-<slug>/` ← per-quest sub-folder when the lesson has a multi-file quest
  - `extras/<key>/transcript.md` ← Circle live-session-recordings post (markdown transcript)
  - `extras/<key>/transcript.txt` ← Circle live-session-recordings post (plain-text transcript)
  - `extras/<key>/chat.txt` ← Zoom chat log attached on the same recording post
  - `setup/<key>/transcript-raw.txt` ← Circle (prework / webinars-kb / live-recordings — discover)
  - `setup/<key>/transcript.md` ← **user-cleaned** (placeholder only — empty file)
  - `references/*.docx` ← Circle program-artifacts (or wherever the course pins reference docs)
  - `notes/` ← user-generated, empty directory only
  - `digital-twin/` ← **excluded** (user-authored Quest 1.1 work, not on Circle)
  - `learning/`, `learn-agent/` ← **excluded** (downstream tooling, not course material)

- Resolve `COURSE_NAMESPACE` against `~/.claude/skills/using-circle-courses/courses.json` before any Circle work. State the resolved namespace, community, and base URL in the first user-facing line. If the namespace's `space_group_slug` or `spaces` map is empty, run the skill's first-time discovery before downloads.
- Authorship boundary — the `using-circle-courses` skill owns all browser automation (tab context, navigation, page reads, attachment downloads). Invoke it via the `Skill` tool with a focused sub-task per subtree; do not call `mcp__claude-in-chrome__*` tools directly from this prompt.
- Idempotence — before fetching any single artifact, test whether the destination file already exists in `DEST_DIR`. If it does, skip the download and note "already present" in the run report. Never overwrite an existing file without explicit user confirmation via `AskUserQuestion`.
- Read-only Circle access — Circle reads do not require pre-confirmation, but **any** action that would modify Circle state (posting, marking complete, sending DMs, reactions) is forbidden in this workflow. If a sub-step seems to require state mutation, stop and ask the user.
- Filename conventions — preserve original Circle filenames exactly when they are sensible (e.g. `kick-off.pdf`). Folder slugs are lowercase kebab-case derived from the lesson/recording title; never invent slugs that are not derivable from Circle metadata.

## Workflow

1. **Resolve inputs.** Parse `$1` as `DEST_DIR` (required) and `$2` as `COURSE_NAMESPACE` (default `aiph2`). Expand `~`. Read `~/.claude/skills/using-circle-courses/courses.json`, confirm the namespace exists, print the resolved namespace + base URL on the first user-facing line.
2. **Confirm destination.** If `DEST_DIR` exists and is non-empty, use `AskUserQuestion` to confirm merge-into-existing before any writes. Otherwise `mkdir -p $DEST_DIR`.
3. **Discover lessons.** Invoke the `using-circle-courses` skill with a sub-task: "list every lesson in the namespace's lessons space; for each, return title, date, lesson URL, attached PDF slides, attached `.docx`/quest folders, and transcript export links." From the returned list, derive each `weeks/<wXdY-YYYY-MM-DD-slug>/` folder name per the naming rule in `Instructions`. Print the planned `weeks/` tree before downloading.
4. **Discover extras.** Invoke the skill with a sub-task: "list every recording in the live-session-recordings space; for each, return title, date, recording URL, transcript export, and Zoom chat log." Derive each `extras/<YYYY-MM-DD-slug>/` folder name. Print the planned `extras/` tree.
5. **Discover setup.** Invoke the skill with a sub-task: "find onboarding/orientation sessions across prework, webinars-kb, and live-recordings spaces; return one entry per session with title, source space, transcript export." Derive each `setup/<slug>/` folder name. Print the planned `setup/` tree.
6. **Discover references.** Invoke the skill with a sub-task: "list reference attachments pinned in `program_artifacts` (or wherever the course pins reference docs); return filename and download URL for each." Print the planned `references/` file list.
7. **Confirm the full plan.** Show the consolidated tree (weeks + extras + setup + references + empty `notes/`) and ask the user to confirm before any downloads.
8. **Create directory shell.** `mkdir -p` every planned folder, plus `notes/`, in one batch.
9. **Download.** For each planned artifact, check if the destination file already exists; if yes skip + log "already present"; otherwise invoke the skill to download into the right path. Group invocations by subtree to keep skill context coherent (one skill call per subtree, not one per file).
10. **Placeholder files.** Create empty `weeks/*/transcripts/transcript.md` and empty `setup/*/transcript.md` for every folder that got a `transcript-raw.*` — these are user-cleaned later, not fetched.
11. **Write `LAYOUT.md`.** Generate `DEST_DIR/LAYOUT.md` with:
    - the full target-layout tree from `Instructions` (verbatim)
    - the source-of-content mapping from `Instructions` (verbatim)
    - "Excluded by design: learning/, learn-agent/, digital-twin/ — see notes below"
    - a short "How to create `digital-twin/`" pointer: it is the user's Quest 1.1 work for their own product; the brief lands inside `weeks/<first-day kick-off lesson>/materials/quest-1.1-digital-twin/`; the user authors `instructions.md` (system prompt for their own AI assistant about their own product), an optional `README.md`, and `data/*.md` knowledge-base files — content is the user's own product (no fixed file count, no fixed dimensions, no example product shape)
    - a per-file table: (path, source = circle URL | user-generated | excluded, status = downloaded | placeholder | skipped-already-present | not-created)
12. **Final report.** Print counts (downloaded, skipped-already-present, placeholder-created, circle-not-found), Circle URLs visited, any planned items the skill could not locate, and the path to `LAYOUT.md`.

## Report

Respond with:
- One-line resolved-namespace banner (e.g. `Resolved namespace → aiph2 (AI Product Heroes 2 on bravecourses.circle.so).`).
- Tree of `DEST_DIR` after population (depth ≤ 3, exactly the shape declared in `Instructions`).
- Counts table: `circle-downloaded`, `placeholder-created`, `skipped-already-present`, `circle-not-found`.
- Bulleted list of any expected Circle items that could not be located, with the space/URL searched.
- Path to the generated `DEST_DIR/LAYOUT.md` so the user can audit the source-of-content mapping in one place.
- Explicit reminder line: `Excluded by design: learning/, learn-agent/ (downstream tooling), digital-twin/ (user-authored quest content for their own product) — these are not part of the course mirror.`
